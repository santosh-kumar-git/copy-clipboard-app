# Cairn Milestone 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a macOS clipboard manager you use daily — copy anything, press a hotkey, fuzzy-find it,
press Enter to get it back — that never records a password and stores nothing readable on disk.

**Architecture:** Electron + TypeScript, with 100% of the clipboard, hotkey and focus work in a
separate Swift agent process speaking NDJSON over stdio. Everything above that boundary is plain
TypeScript behind narrow interfaces, tested against a fake agent that replays recorded transcripts —
so no test needs a real clipboard or an OS permission.

**Tech Stack:** Electron 44.1.1 (pinned exact) · TypeScript 5.9 strict · Swift 6.3.3 (Command Line
Tools only, no Xcode) · Svelte 5 · zod 4 · vitest 4 · electron-vite 5 · Vite 7.3.6 · `sharp` ·
`@leeoniya/ufuzzy` · `node:crypto` only for all cryptography · npm workspaces on Node 24.20.0.

**Spec:** [`../specs/2026-09-02-cairn-clipboard-manager-design.md`](../specs/2026-09-02-cairn-clipboard-manager-design.md)
— read §4 (modules), §6 (degraded modes), §7 (testing), §8 (build order) and **§11 (security model)**.

**Frozen contract:** [`2026-09-02-cairn-m1/00-contract.md`](2026-09-02-cairn-m1/00-contract.md) — the
single source of truth for every shared type, file path, config file and dependency version. Ten task
sections were written independently against it. **Read it before any task, and match it exactly.**
Where a task section and the contract disagree, the contract wins and the disagreement is a bug worth
reporting.

This plan is split into one file per task because it totals ~31,000 lines; a single file that size will
not render on GitHub, and each task is what one implementer reads in one sitting anyway.

## Global Constraints

Every task's requirements implicitly include this section. Values are exact and were verified against
real installs on the target machine, not assumed.

**Toolchain**
- `.nvmrc` = `24.20.0`. This governs **build tooling only** — main-process code runs on Electron's
  bundled Node 24. The machine's default Node 20.16.0 is below the electron-vite 5 / Vite 7 floor and
  is where `node-gyp` dies with an undici `TypeError`.
- Electron pinned **exactly** at `44.1.1`. Vite pinned at `7.3.6`, **not** 8.x — electron-vite 5.0.0's
  peer range is `^5 || ^6 || ^7`. Consequently `@sveltejs/vite-plugin-svelte` is `6.2.4`, not 7.x.
- npm workspaces. Never Yarn PnP.
- Swift builds with `swiftc` from Command Line Tools. Full Xcode is **not** required and must not
  become required.

**Native-dependency invariant, enforced by CI**
- `@electron/rebuild` appears nowhere in the dependency tree. `npm run guard:no-rebuild` fails the
  build if it does. (Note for M3: `app-builder-lib@26.15.3` declares `@electron/rebuild ^4.0.4`, so
  packaging will need an npm `overrides` entry or the guard will correctly stop it.)
- Every native artifact is either Node-API (`sharp`) or a standalone process (the Swift agent). No
  `node-gyp`, no V8 ABI, no rebuild step, ever.
- `.npmrc` sets `ignore-scripts=true`. `sharp` still works because its prebuilds ship as optional deps.
  Electron's binary comes from one explicit, audited `npm run bootstrap`
  (`node node_modules/electron/install.js`) — visible in `package.json` rather than buried in an
  allowlist.

**Module and packaging rules**
- `@cairn/*` packages are consumed as **ESM TypeScript source** (`exports: { ".": "./src/index.ts" }`)
  with **no build step** — no tsup, no `dist/`. vitest resolves them, electron-vite inlines them, and
  `node tools/x.ts` runs them via Node 24's built-in type stripping.
- The Electron **preload must be CJS**. Measured on 44.1.1: a `.mjs` preload in a `sandbox: true`
  window fails the page load with `ERR_FAILED (-2)`; the CJS preload works. This is a hard constraint.
- The `@cairn/protocol` barrel has exactly **eleven** export lines. Task 1 writes two (`./constants`,
  `./testing`); Task 2 appends nine.

**Testing**
- vitest with **three** projects: `unit`, `security`, `renderer`. Task 1 creates all three.
- CI runs a bare **`npm test`** (`vitest run`, no `--project`). Measured: a bare run exits **0** even
  when one project matches no files, while `vitest run --project renderer` on an empty project exits
  **1**. So the bare form both covers every project and survives Tasks 1–9 with the renderer project
  empty. A per-project CI step list would silently skip any project added later — never introduce one.
- Tests live beside their source as `*.test.ts`. Security tests are `*.security.test.ts`.
- Every clock is **injected**, so retention and TTL tests are deterministic.
- Clipboard behaviour is verified by replaying whole recorded NDJSON sessions, not by per-format unit
  tests alone — that is what catches debounce, duplicate-notify and self-write-loop bugs.
- Committed transcripts contain **synthetic content only**. `tools/record-transcript.ts` captures real
  sessions, so its raw output is unreviewed real clipboard data; `*.raw.ndjson` and `unscrubbed/` are
  gitignored and `npm run scan:transcripts` must pass over what is committed.

**Security — the primary constraint on this project.** Spec §11 is binding. Each is a real test, not a
comment.
1. **Clipboard bytes never touch the disk unencrypted.** No spool files, no temp files, no plaintext
   caches. Representations ≥64 KiB stream as hash-verified `rep.chunk` events over stdout and are
   reassembled **in memory**.
2. `crashReporter` is **never initialised** — enforced as a source-identifier ban, because a runtime
   check proves nothing (`getUploadToServer()` returns `false` whether or not `start()` was called).
3. No telemetry, no analytics, **no socket bound at startup** — asserted.
4. **Copied HTML is never rendered as HTML.** No `{@html` anywhere in the renderer, including comments
   (`.svelte` is scanned raw), plus a test that an `<img onerror>` payload renders as literal text.
5. **No shell on the capture or recall path** — `execSync`, `execFile`, `spawnSync`, `shell: true`,
   `/bin/sh`, `osascript` all banned under `packages/**` and `apps/desktop/**`. A copied file path
   interpolated into a command line is remote code execution triggered by a copy.
6. The Swift agent has its own ban on **filesystem *and* network** APIs — it holds clipboard bytes
   first and sits outside every other guard's roots.
7. `LogFields` is metadata-only with a closed `LogEvent` union, so logging raw content is a **compile**
   error — proven by a type-level test — plus a runtime test that copies a canary and greps all output.
8. Renderer: `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`, `webSecurity` on,
   local files only, strict CSP with no `unsafe-inline`, navigation and `window.open` denied, DevTools
   off in packaged builds, and an **enumerated** preload surface — no `invoke(channel, ...)`
   passthrough.
9. **No custom URI scheme** (`setAsDefaultProtocolClient` banned), no local control socket, no
   unauthenticated local API.
10. Secrets are masked **at ingest**, so the in-memory index never holds a raw secret. 5-minute TTL,
    never pinnable, and `assertSyncable()` throws for every flag.
11. Data dir `0700`, every file `0600`. The master key buffer is zero-filled on lock, asserted on
    buffer **contents**.
12. Store tamper-evidence: AAD binds line + seq, a `prevRecordHash` chain catches a **deleted** line,
    duplicate and truncated lines are detected, a torn trailing line is tolerated as a crash, the
    `CHECKPOINT` is sealed inside the encrypted log, and blobs `fsync` before the referencing event is
    appended.
13. The headline test: copy a canary string, then scan **every byte of every file** under the data dir
    and assert it does not appear — with a planted plaintext file proving the walker is not vacuous.

**Two spec errors the plan corrects — do not "restore" them**
- The spec's entropy rule (`> 4.0 bits/char`) **fails its own false-positive corpus**: a long tracking
  URL scores 4.317 and minified JS 4.622. The contract freezes a corrected per-run rule (20..512 chars,
  token charset, skipping URL-ish, path-ish and code-ish runs) with a 13-entry false-positive corpus
  and a 4-entry high-entropy corpus it must pass.
- `safeStorage.getSelectedStorageBackend` **does not exist at runtime on macOS** in Electron 44 despite
  the typings declaring it unconditionally. `probeBackend()` guards with `typeof … === 'function'`; a
  missing API is not a weak backend.
- Related: `scryptSync` at `N=2^17, r=8` needs an explicit `maxmem: 192 MiB`, because those parameters
  require 128 MiB against Node's 32 MiB default cap and it otherwise throws
  `ERR_CRYPTO_INVALID_SCRYPT_PARAMS`.

**Secret-shaped test data must never be committed literally.** GitHub push protection scans every push
and rejects the entire push — `GH013: Repository rule violations found` — when a file matches a partner
secret pattern, regardless of whether the value is synthetic. This was measured, not predicted: a fake
Stripe key in Task 7's detector corpus blocked this plan's own first push. Any fixture or assertion
needing a pattern GitHub partners on (Stripe, Slack app tokens, npm, Twilio, SendGrid, a full-length AWS
id) assembles it from fragments at runtime — `'sk_' + 'live_…'` — or stores it as a `textParts` array
that the loader joins. Structurally invalid samples are fine: the plan's AWS ids are 17 characters where
a real one is 20. This is the same reason Task 3's in-package scanner spells its own needles as
`'mkd' + 'temp'`, and neither trick may be "simplified" away.

**Git workflow**
- **Never commit to `main`.** Each task branches from a freshly fetched `origin/main` as
  `m1/<NN>-<slug>`, and its final step pushes that branch for the repository owner to merge via PR.
- Conventional commit messages (`feat(store): …`, `test(protocol): …`). **No `Co-Authored-By` and no
  AI-attribution trailer of any kind** — commits carry the owner's name only.

**Cross-task references cite step TITLES, not step numbers.** Step numbers shift whenever any task
inserts a step; three rounds of review were spent repairing exactly that breakage. Within a single task,
numbered references are fine and must be correct.

## What Milestone 1 deliberately does not include

Deferred to later milestones (spec §8), so do not add them here: auto-paste and the macOS Accessibility
permission flow (M2), the per-app exclusion list (M2), packaging, signing, notarization, login item,
tray and auto-update (M3), the Windows and Linux agents (M4), and every part of phone sync — the Noise
protocol, mDNS, QR pairing, the sync server (M5–M6).

Pressing Enter in M1 puts the item on the real clipboard and toasts *"Copied — press Cmd+V"*. That is
not a stub: it is exactly the M2 behaviour when macOS Accessibility is denied, so the code path is
permanent.
