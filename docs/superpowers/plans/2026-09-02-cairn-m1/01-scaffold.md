### Task 1: Repo scaffold, toolchain, the security CI harness, and the two day-0 spikes

This task turns an empty-but-real git repo (it already has `.gitignore`, `LICENSE`, `README.md`,
`ROADMAP.md` and the spec — **do not recreate any of them**) into a workspace where `npm test`,
`npm run typecheck`, `npm run test:security` and `npm run guard:no-rebuild` all pass, a bare hardened
Electron window opens, and the two spikes spec §8 mandates have real recorded answers.

Nothing here is throwaway. In particular the palette window is created **already hardened** — there
is deliberately never a commit in this repo's history in which an Electron window with clipboard
history behind it has `nodeIntegration` on or a loose CSP.

**`npm run doctor` is NOT in this task.** The contract's §0 table puts `tools/doctor.ts` /
`npm run doctor` in M2 and says of everything in that table: *do not add, do not stub, do not
reference from a task section*. The committed `README.md` documents the command under Development,
which is now wrong for M1 — so Step 2 replaces that one README line rather than shipping a command
M1 does not have. `README.md` is therefore the second *Modify* entry, edited surgically, one line.

**Files this task creates that the contract's §1 file tree now lists (it was updated to match, so these
are no longer deviations):** `security/source-scan.ts` and
`security/source-scan.test.ts` (a test-only helper that the source-identifier bans in this task, the
shell/IPC task and the palette task all share, plus the unit test that proves its comment stripping
cannot be fooled), `fixtures/guard/**` (two committed dependency-tree fixtures, five files in
all, that make the `no-electron-rebuild` guard's *failure* path a test rather than a hope) and
`apps/desktop/renderer/src/vite-env.d.ts` (one triple-slash reference line, and the reason is
measured in Step 6: with `apps/desktop/renderer/tsconfig.json` correctly narrowed to
`["src/**/*.ts", "src/**/*.svelte"]`, an empty `renderer/src/` makes `svelte-check` exit **1** with
`No inputs were found in config file`, which would fail `npm run typecheck` on every branch from this
task until the palette task lands the first renderer source) — plus `spikes/**` and
`.github/workflows/ci.yml`. None of them is product code.

`packages/protocol/src/testing.ts` and `packages/protocol/src/testing.test.ts` are **not** deviations:
contract §1 lists both and contract §7 specifies the helper's two lines verbatim. This task creates
them; the protocol task verifies them and must not recreate them.

- [ ] **Step 16: Write the `no-electron-rebuild` guard.**

Spec §2 makes this a CI-enforced invariant: every native artefact in this repo is either Node-API
(`sharp`) or a standalone process (the agents), and `@electron/rebuild` / `node-gyp` are the only
things that would drag V8-ABI rebuilds back in. It scans the lockfile **and** every manifest, because
a range in a manifest is a future transitive install.

`scripts/guard-no-electron-rebuild.mjs`:

```js
#!/usr/bin/env node
// Fails the build if @electron/rebuild or node-gyp appear anywhere: a direct dependency, a
// transitive one, or a lockfile entry. Spec §2 makes this a CI-enforced invariant, because it is
// the only thing that would drag V8-ABI rebuilds back into a repo whose native artefacts are all
// either Node-API (sharp) or standalone processes (the agents).
import { existsSync, readFileSync, readdirSync } from 'node:fs'
import { join } from 'node:path'

const BANNED = ['@electron/rebuild', 'electron-rebuild', 'node-gyp', '@electron/node-gyp']
const hits = []

if (!existsSync('package-lock.json')) {
  console.error('guard: package-lock.json is missing — run `npm install` and commit the lockfile')
  process.exit(2)
}
const lock = JSON.parse(readFileSync('package-lock.json', 'utf8'))
const lockEntries = Object.keys(lock.packages ?? {})
for (const p of lockEntries) {
  for (const b of BANNED) {
    if (p === `node_modules/${b}` || p.endsWith(`/node_modules/${b}`)) hits.push(`package-lock.json: ${p}`)
  }
}

const manifests = ['package.json']
for (const group of ['packages', 'apps', 'agents']) {
  if (!existsSync(group)) continue
  for (const d of readdirSync(group)) {
    const m = join(group, d, 'package.json')
    if (existsSync(m)) manifests.push(m)
  }
}
for (const m of manifests) {
  const pkg = JSON.parse(readFileSync(m, 'utf8'))
  for (const field of ['dependencies', 'devDependencies', 'optionalDependencies', 'peerDependencies']) {
    for (const name of Object.keys(pkg[field] ?? {})) {
      if (BANNED.includes(name)) hits.push(`${m}: ${field}.${name}`)
    }
  }
}

if (hits.length > 0) {
  console.error('guard-no-electron-rebuild FAILED. Banned packages found:')
  for (const h of hits) console.error('  - ' + h)
  console.error('\nEvery native artefact must be Node-API (sharp) or a standalone process (the agents).')
  process.exit(1)
}
console.log(`guard-no-electron-rebuild OK — scanned ${lockEntries.length} lockfile entries and ${manifests.length} manifests`)
```

It reads `package-lock.json` and `{packages,apps,agents}/*/package.json` **relative to `cwd`** — that
is exactly what lets the fixture trees be tested by spawning it with a different `cwd`, with no flags
and no injection seam.

- [ ] **Step 17: Write the scanner's own unit test first — its comment stripping is a security control.**

Every source ban in this repo runs through one function, so a bug in that function silently disables
the `crashReporter` ban, the socket ban, the shell-execution ban, the URI-scheme ban and the
raw-HTML-directive ban all at once. That makes the scanner's own behaviour worth a plain unit test
before the scanner exists.

Two rules, and both are load-bearing:

1. **Bans match non-comment lines only**, because a control that trips on its own documentation gets
   deleted within a week, and a deleted ban is a missing control. Two files in this plan already prove
   the case, and both are real: `packages/protocol/src/agent.ts` documents that "an oversized rep
   streams over the stdout pipe, it never spools to a file" — the word `spool` is a banned identifier
   in the store task's no-plaintext-on-disk scan — and `apps/desktop/main/src/config.ts` documents in
   a doc comment exactly why it does *not* use `writeFileSync(p, d, {mode: 0o600})`, which is another
   banned identifier in that same scan. A raw substring scan would make both files failures for
   saying the right thing. The definition of every ban in this plan is therefore "no **non-comment**
   line names it". (Note what this rule does *not* excuse: the wiring task's `DELIBERATELY ABSENT`
   comment block in `apps/desktop/main/src/index.ts` still spells out **no** banned identifier, so
   that block would survive a raw scan too. Belt and braces, deliberately.)
2. **A comment stripper that can be fooled is worse than none.** `const s = "//"; crashReporter.start()`
   must still be a hit, so stripping is quote-aware, not a `line.split('//')[0]`.

Comment stripping applies to code extensions only (`.ts`, `.js`, `.mjs`, `.cjs`, `.swift`).
`.html`, `.svelte`, `.json` and `.plist` are matched raw through `findRawInSources`, because the CSP
meta tag lives inside an HTML comment's sibling markup and quotes there are content, not syntax.

The reader tests build their **own** two-file tree in a temp directory and pass it as an absolute
root, because `sourceFiles` accepts absolute roots. That keeps this step independent of
`apps/desktop/**`, which does not exist until Step 22 — a scanner test that depended on product files
would be unrunnable in the only order this task can be executed in. The tree is removed in
`afterAll`, the same discipline contract §7's `tempStoreDir()` establishes, so nothing is left in
`TMPDIR` for the later no-plaintext-on-disk test to trip over. Nothing written here is clipboard
data: two literal strings, chosen to be the two cases that matter.

- [ ] **Step 18: Write the shared source scanner, then run both suites green.**

Eight security tests will need "read every source file under these roots and look for a string", so
it lives in one place. It is test-only code and lives under `security/`, which is deliberately **not**
one of the roots any test scans — otherwise a test that bans an identifier would trip on its own
source.

`security/source-scan.ts`:

```ts
import { readFileSync, readdirSync, statSync } from 'node:fs'
import { dirname, extname, isAbsolute, join, relative } from 'node:path'
import { fileURLToPath } from 'node:url'

/** Repo root, resolved from this file, so a test's cwd never matters. */
export const REPO_ROOT = join(dirname(fileURLToPath(import.meta.url)), '..')

const SOURCE_EXTENSIONS = new Set([
  '.ts', '.js', '.mjs', '.cjs', '.svelte', '.html', '.swift', '.json', '.plist',
])
/** Only these have C-style comments. `.svelte`, `.html`, `.json` and `.plist` are matched raw. */
const CODE_EXTENSIONS = new Set(['.ts', '.js', '.mjs', '.cjs', '.swift'])
const SKIP_DIRS = new Set(['node_modules', 'out', 'build', 'coverage', '.git', '.vitest-reports'])

/** Every source file under `roots` (repo-relative, or absolute). A missing root is skipped. */
export function sourceFiles(roots: readonly string[]): string[] {
  const files: string[] = []
  for (const root of roots) {
    const abs = isAbsolute(root) ? root : join(REPO_ROOT, root)
    let entries: string[]
    try {
      statSync(abs)
      entries = readdirSync(abs, { recursive: true }) as string[]
    } catch {
      continue
    }
    for (const entry of entries) {
      if (entry.split('/').some((p) => SKIP_DIRS.has(p))) continue
      if (!SOURCE_EXTENSIONS.has(extname(entry))) continue
      const full = join(abs, entry)
      if (!statSync(full).isFile()) continue
      files.push(full)
    }
  }
  return files.sort()
}

/**
 * `text` with `//` and block comments removed and every newline preserved, so line numbers still
 * match the file on disk. Quote-aware on purpose: `const s = "//"; crashReporter.start()` must stay
 * a hit, and a backslash escape is consumed as a pair so `/^https?:\/\//` is not read as a comment.
 * This is the whole reason a ban can be defined as "no non-comment line names it".
 */
export function stripComments(text: string): string {
  let out = ''
  let i = 0
  let state: 'code' | 'quote' | 'line' | 'block' = 'code'
  let quote = ''
  while (i < text.length) {
    const c = text[i] ?? ''
    const next = text[i + 1] ?? ''
    if (state === 'code') {
      if (c === '\\') { out += c + next; i += 2; continue }
      if (c === '/' && next === '/') { state = 'line'; i += 2; continue }
      if (c === '/' && next === '*') { state = 'block'; i += 2; continue }
      if (c === "'" || c === '"' || c === '`') { state = 'quote'; quote = c; out += c; i += 1; continue }
      out += c
      i += 1
      continue
    }
    if (state === 'quote') {
      if (c === '\\') { out += c + next; i += 2; continue }
      if (c === quote) { state = 'code'; quote = '' }
      out += c
      i += 1
      continue
    }
    if (state === 'line') {
      if (c === '\n') { state = 'code'; out += c }
      i += 1
      continue
    }
    if (c === '*' && next === '/') { state = 'code'; i += 2; continue }
    if (c === '\n') out += c
    i += 1
  }
  return out
}

/** A file's literal bytes as UTF-8, with no stripping. */
export function readSource(file: string): string {
  return readFileSync(file, 'utf8')
}

export interface SourceHit {
  readonly file: string
  readonly line: number
  readonly text: string
}

function scan(needle: string, roots: readonly string[], strip: boolean): SourceHit[] {
  const hits: SourceHit[] = []
  for (const file of sourceFiles(roots)) {
    const raw = readSource(file)
    const stripped = strip && CODE_EXTENSIONS.has(extname(file)) ? stripComments(raw) : raw
    const rawLines = raw.split('\n')
    stripped.split('\n').forEach((text, i) => {
      if (text.includes(needle)) {
        hits.push({ file: relative(REPO_ROOT, file), line: i + 1, text: (rawLines[i] ?? text).trim() })
      }
    })
  }
  return hits
}

/**
 * Every NON-COMMENT line under `roots` containing `needle`, as a plain substring. This is the
 * function every source ban uses: `apps/desktop/main/src/index.ts` documents the absence of
 * `crashReporter`, `net.createServer` and `setAsDefaultProtocolClient` in a comment block on
 * purpose, and a ban that tripped on its own documentation would be deleted within a week.
 * The reported `text` is the RAW line, so a failure message shows what is actually in the file.
 */
export function findInSources(needle: string, roots: readonly string[]): SourceHit[] {
  return scan(needle, roots, true)
}

/** Every line, comments included — for the CSP meta tag and any other assertion about literal text. */
export function findRawInSources(needle: string, roots: readonly string[]): SourceHit[] {
  return scan(needle, roots, false)
}

/** A one-line message a failing assertion can print without a debugger. */
export function formatHits(hits: readonly SourceHit[]): string {
  return hits.map((h) => `${h.file}:${h.line}: ${h.text}`).join('\n')
}

- [ ] **Step 25: Write the failing `crashReporter` security test.**

- [ ] **Step 31: Write the CI workflow, then run the same command line locally.**

Spec §11's controls are "verified as a CI job, not as a habit", so the job exists from day 0. The
runner is macOS because `swiftc` and the whole M1 demo are macOS. `npm ci` (not `npm install`) is
what makes the committed lockfile authoritative, and `guard:no-rebuild` runs **before** anything else
so a banned build path fails in seconds.

The last gate needs explaining, because it is the one step in this file that guards data rather than
code. `tools/record-transcript.ts` (Swift-agent task) is the only tool in the repo that writes real
clipboard bytes to a file, and that task's instructions record five fixtures off a live pasteboard and
promote them into `fixtures/agent-transcripts/`. Without a scan, one real AWS key or password copied
during a recording window is in git permanently. `scripts/scan-transcripts.mjs` and the transcripts
arrive together in that task, so this workflow is written to be **loud rather than conditional**: if a
transcript is committed and the scanner is missing, CI fails; only the state "no transcripts and no
scanner" is allowed to pass, and that state is exactly this branch.

The test step is one `npm test`, not one step per vitest project, and that is a measured decision.
`vitest run` exits **0** when one project matches no test files as long as another project does; a
named `npx vitest run --project renderer` exits **1** with `No test files found, exiting with code 1`.
Both verified on vitest 4.1.11. So a per-project step list either goes red on every branch from this
task until the palette task lands renderer tests, or it omits the `renderer` project entirely and
thirty-eight renderer assertions — including the raw-HTML escaping ones — pass locally and never run
in CI. `npm test` has neither failure mode and cannot silently miss a project added later.

- The paste keycode is resolved from the current `TISInputSource`, never hardcoded to 9.
- `swiftc -O -whole-module-optimization` over AppKit + Carbon + CryptoKit + Foundation links in

- `JSONEncoder` emits keys in a **non-deterministic order across runs** unless

- `safeStorage.getSelectedStorageBackend` **does not exist at runtime on macOS** in Electron 44.1.1 —

- `app.setName('Cairn')` must run before the first `app.getPath('userData')`; without it Electron 44

- M1 needs **zero TCC grants**: NSPasteboard reads, NSWorkspace attribution and Carbon hotkeys are

- [ ] **Step 33: Spike (a) — write and compile the `type:'panel'` probe.**

Spec §8, timeboxed. The question: **does `BrowserWindow({type:'panel'})` still yield a real NSPanel on
Electron 44?** Electron's own typings declare `type?: string` — no union, no validation — so the
compiler will never tell you, and a wrong assumption here shows up as a palette that steals focus
from the app you are trying to paste into.

Two properties matter, and they come from two *different* controls, which is the whole reason this
spike runs three configurations rather than one:

- **Not stealing focus** is the NSPanel property (a nonactivating panel can be the key window while
  its app stays inactive). Observed by asking the OS who is frontmost *after* we show the window.
- **Not appearing in Cmd-Tab** is the *activation policy* property (`accessory`, i.e. `LSUIElement`),
  not NSPanel. Observed by eye.

`spikes/electron-panel/frontmost.swift` — a permission-free observer; it never asks for
`kCGWindowName`, so it needs neither Accessibility nor Screen Recording:

// Prints the frontmost app and every on-screen window's owner + CG layer.
// Neither call needs Accessibility or Screen Recording: we never ask for kCGWindowName.

print("frontmost=\(front?.bundleIdentifier ?? "nil") pid=\(front?.processIdentifier ?? -1)")
let opts: CGWindowListOption = [.optionOnScreenOnly, .excludeDesktopElements]
guard let info = CGWindowListCopyWindowInfo(opts, kCGNullWindowID) as? [[String: Any]] else {
  print("no window list"); exit(1)
}
let needle = CommandLine.arguments.count > 1 ? CommandLine.arguments[1] : ""
for w in info {
  let owner = w[kCGWindowOwnerName as String] as? String ?? "?"
  if !needle.isEmpty && !owner.lowercased().contains(needle.lowercased()) { continue }
  let layer = w[kCGWindowLayer as String] as? Int ?? -999
  let num = w[kCGWindowNumber as String] as? Int ?? -1
  let bounds = w[kCGWindowBounds as String] as? [String: Any] ?? [:]
  print("window owner=\(owner) layer=\(layer) id=\(num) bounds=\(bounds["Width"] ?? "?")x\(bounds["Height"] ?? "?")")
}
```

// behaviour will. Run it three ways and compare:
